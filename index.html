rubrapack

A tool that builds Windows installers (.msi) and MSIX packages from one small text file.

Write what to install in a few lines of TOML; rubrapack writes the installer with its dialogs in your users' language, signs it and checks it - one self-contained program, on Linux or Windows, with no XML and no GUIDs to track.

DownloadGitHubManualManual (PDF)TutorialRelease notes

Background

A proper Windows installer - Program Files, the Start menu, an entry in Installed apps, upgrades and a clean removal - usually means XML, a table editor or a Windows build machine, and component GUIDs to keep track of by hand.

rubrapack was written so that a short, readable source and one command are enough, on the same Linux CI runner that builds the rest of a release, and so that the mistakes that break an installation or an upgrade are found before users meet them. It is plain C with no dependencies, written from the public specifications and checked against Windows.

Features

This file makes this installer

The example's whole source is about forty lines of TOML: [package] with name, version and upgrade code, ui = "features", license = "LICENSE.txt", languages, two features, folders, files and a Start menu shortcut. rubrapack build hello.toml -o hello.msi turns it into the installer on this page; component GUIDs, product codes and tables rubrapack derives.

The dialogs, written for you

One line chooses the set - welcome, license, install folder, optional parts, ready - and rubrapack writes the dialogs, their texts and the upgrade rules. Next stays off until the license is accepted.

The install folder

Browse opens Windows' own folder picker, and the folder chosen is remembered for the next upgrade.

Progress, in detail

A details box shows each file and setting as Windows writes it, and the finished page can start the program and keeps the log of what was installed (both from the manual's tutorial example).

Change, Repair, Remove

Run the installer again, or from Installed apps: the same package changes the optional parts, repairs or removes the product.

In your users' language

languages = ["ko", "ja", "de", "ar"] puts them all in one package: a language page comes first, with the user's Windows language preselected. 48 languages are built in, and rubrapack's own messages come in them too (--lang).

Right to left

Arabic, Hebrew and the other right-to-left languages get their dialogs laid out from the right.

Upgrades checked before release

rubrapack lint new.msi --previous old.msi compares two versions and catches what would break an upgrade - a changed upgrade code would install the new version beside the old one. lint also checks any MSI or MSIX, whoever made it.

Signed, and the same bytes every time

Authenticode signing with a PFX or PEM file, a hardware token (PKCS#11) or the Windows certificate store, with an RFC 3161 timestamp; verify checks a signature. With --reproducible the same source gives the same bytes on Linux and Windows.

MSIX from the same source

Add two small tables and the same file also builds a signed MSIX package, or a bundle for x64, x86 and Arm64 with --arch.

Notes

  • Quick start: rubrapack new app -i asks a few questions and writes app.toml; rubrapack build app.toml -o app.msi builds the installer. On Linux make the download executable first (chmod +x); on Windows run the .exe from a terminal.
  • One program of about 12 MB with 48 languages built in. The Linux program needs only the C library; the Windows program uses only DLLs that are part of Windows, not even msi.dll.
  • Errors read file:line:column: error[RPnnnn], often with the fix, and the exit codes are fixed - easy for a script, a CI job or an AI assistant to act on.
  • Also: transforms (.mst) and patches (.msp), merge modules, a setup.exe that installs several packages in order, a winget manifest and a Windows Sandbox file to try the package in. Not a WiX front end: it does not read .wxs files.
  • Every feature is tested on Linux and by installing, running, repairing, upgrading and removing the packages on Windows 11 (x64). Not tested on real hardware yet: Arm64 packages, hardware PKCS#11 tokens, a native build on Windows.
