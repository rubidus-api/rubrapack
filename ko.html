rubrapack

작은 텍스트 파일 하나로 Windows 설치 프로그램(.msi)과 MSIX 패키지를 만드는 도구입니다.

설치할 것을 TOML 몇 줄로 적으면 rubrapack 이 사용자의 언어로 된 설치 화면까지 넣어 설치 프로그램을 만들고, 서명하고, 검사합니다. XML 도 GUID 관리도 없이, 따로 설치할 것 없는 프로그램 하나로 Linux 에서도 Windows 에서도.

배경

Program Files 에 설치되고, 시작 메뉴와 설치된 앱 목록에 나타나고, 업그레이드와 깨끗한 제거가 되는 제대로 된 Windows 설치 프로그램을 만들려면 보통 XML 이나 테이블 편집기, 또는 Windows 빌드 머신이 필요하고, 구성 요소 GUID 도 손으로 관리해야 합니다.

rubrapack 은 짧고 읽기 쉬운 소스와 명령 하나면 되도록, 릴리스의 나머지를 만드는 그 Linux CI 에서 되도록, 그리고 설치나 업그레이드를 깨뜨릴 실수를 사용자보다 먼저 찾도록 만들었습니다. 의존성 없는 C 로, 공개된 명세를 보고 쓰고 Windows 에서 확인했습니다.

기능

이 파일이 이 설치 프로그램이 됩니다

예제의 소스 전체가 TOML 40줄 남짓입니다. 이름·버전·업그레이드 코드를 적은 [package], ui = "features", license = "LICENSE.txt", languages, 기능 두 개, 폴더, 파일, 시작 메뉴 바로 가기. rubrapack build hello.toml -o hello.msi 로 이 페이지의 설치 프로그램이 나오고, 구성 요소 GUID·제품 코드·테이블은 rubrapack 이 정합니다.

대화 상자는 rubrapack 이 씁니다

시작, 사용권, 설치 폴더, 선택 기능, 준비 화면을 한 줄로 고르면 대화 상자와 문구와 업그레이드 규칙은 rubrapack 이 씁니다. 사용권에 동의하기 전에는 다음으로 갈 수 없습니다.

설치 폴더

찾아보기는 Windows 의 폴더 선택 창을 열고, 고른 폴더는 다음 업그레이드 때도 기억됩니다.

자세한 진행

자세히 보기 상자에 Windows 가 쓰는 파일과 설정이 하나씩 나오고, 마침 화면에서는 프로그램을 바로 실행하고 설치한 내용을 볼 수 있습니다(둘 다 매뉴얼 튜토리얼의 예제).

변경·복구·제거

설치 프로그램을 다시 실행하거나 설치된 앱 목록에서, 같은 패키지로 선택 기능을 바꾸고, 복구하고, 제거합니다.

사용자의 언어로

languages = ["ko", "ja", "de", "ar"] 한 줄이면 패키지 하나에 모두 들어갑니다. 언어 선택 화면이 먼저 나오고 사용자의 Windows 언어가 골라져 있습니다. 48개 언어가 들어 있고, rubrapack 자신의 메시지도 그 언어로 나옵니다(--lang).

오른쪽에서 왼쪽으로

아랍어, 히브리어처럼 오른쪽에서 왼쪽으로 쓰는 언어는 대화 상자도 오른쪽부터 배치됩니다.

업그레이드는 내보내기 전에 검사

rubrapack lint new.msi --previous old.msi 가 두 버전을 비교해 업그레이드를 깨뜨릴 실수를 잡습니다. 업그레이드 코드가 바뀌면 새 버전이 이전 버전 옆에 따로 설치되는 것 같은 실수입니다. lint 는 누가 만든 MSI·MSIX 든 검사합니다.

서명, 그리고 언제나 같은 바이트

PFX·PEM 파일, 하드웨어 토큰(PKCS#11), Windows 인증서 저장소의 키로 Authenticode 서명을 하고 RFC 3161 타임스탬프를 붙이며, verify 가 서명을 확인합니다. --reproducible 를 주면 같은 소스는 Linux 와 Windows 에서 같은 바이트가 됩니다.

같은 소스로 MSIX 까지

작은 테이블 두 개를 더하면 같은 파일로 서명된 MSIX 패키지도, --arch 로 x64·x86·Arm64 묶음도 만듭니다.

덧붙임

  • 빠른 시작: rubrapack new app -i 가 몇 가지를 묻고 app.toml 을 쓰고, rubrapack build app.toml -o app.msi 가 설치 프로그램을 만듭니다. Linux 에서는 받은 파일에 먼저 실행 권한을 주고(chmod +x), Windows 에서는 터미널에서 .exe 를 실행합니다.
  • 약 12 MB 프로그램 하나에 48개 언어가 들어 있습니다. Linux 용은 C 라이브러리만, Windows 용은 Windows 에 원래 있는 DLL 만 씁니다. msi.dll 조차 쓰지 않습니다.
  • 오류는 파일:줄:칸: 오류[RPnnnn] 형태로 고칠 방법과 함께 나오고 종료 코드가 정해져 있어, 스크립트나 CI, AI 도우미가 다루기 쉽습니다.
  • 그 밖에 변환(.mst)과 패치(.msp), 병합 모듈, 여러 패키지를 차례로 설치하는 setup.exe, winget 매니페스트, 패키지를 시험해 볼 Windows 샌드박스 파일도 만듭니다. WiX 프런트엔드가 아니므로 .wxs 파일은 읽지 않습니다.
  • 모든 기능을 Linux 에서 시험하고, Windows 11(x64)에서 패키지를 설치·실행·복구·업그레이드·제거해 시험합니다. 실제 장치로 아직 시험하지 못한 것: Arm64 패키지, 하드웨어 PKCS#11 토큰, Windows 에서의 직접 빌드.
